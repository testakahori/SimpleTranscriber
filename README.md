# 🎙️ つよつよ文字起こし＆議事録ツール (SimpleTranscriber)

会議の音声や動画を入れると、文字起こし・議事録・要約を作って `output/` に保存するツールです。
すべて自分のPCの中で動きます。文字起こしは Whisper、校正・議事録づくりはローカルの [Ollama](https://ollama.com) 上で動く gemma4 が担当し、音声や文字起こしを外部のサービスに送ることはありません。機密の会議にも使えます。

## 使い方の流れ

作業は3段階に分かれていて、段階ごとに人が確認して直せます。

1. **① 🚀 文字起こし開始**
   音声を文字にし、誰が話したかを割り当てます。LLMはまだ使いません。
2. **確認と修正、② ✍️ AI校正**
   「話者に名前を付ける」で話者名を確定し、気になる発言は直接直します。
   AI校正を押すと、gemma4 が誤変換を前後の文脈から直します。推測で直した所は<span style="color:red">赤字</span>になります。途中で止めても続きから再開できます。
3. **③ 📋 議事録を作る**
   直した後の文字起こしから議事録を作ります。「💡 要約と考察を作る」で3行要約と考察も作れます。

認識中は途中結果を自動保存します。途中で止まった場合は「📂 過去の結果を開く」の 🔄 を押して履歴を更新し、該当する結果を選んで「▶ 途中保存から再開」を押してください。アプリの再起動後も再開できます。新しい形式の途中保存には音声と認識設定も含むので、元ファイルの再選択は不要です。画面の現在の設定ではなく、保存時の設定で続きを処理し、同じ保存先に完成版を書き出します。

自分で止める場合は、開始ボタンの下の **「⏸ 一時停止（保存して止める）」** を押してください。「受け付けました」の表示後、処理中の認識区間・補完区間が終わると最新の本文を保存し、一時停止した結果を画面に開きます。「一時停止しました」と表示されてからアプリを閉じてください。その場でも、あとでアプリを開き直した後でも「▶ 途中保存から再開」で続行できます。

音声準備・モデル読み込み・話者識別の最中は、その処理が戻るまで停止を待ちます。準備中の停止要求は再開用音声を保存してから反映します。処理が応答しない場合は即時に強制終了する機能ではありません。完成版の保存を始めた直後に押した場合は、完成版を保存して終了します。複数ファイルの処理では後続ファイルも始めずに止め、まだ着手していないファイル名を表示します。未着手のファイルはあとで選び直して開始してください。このボタンは、その画面で開始・再開した文字起こしを対象にします。AI校正・議事録生成には適用しません。

主認識の途中では、語頭を欠かさないよう保存位置の約2秒前（発言にかかる場合はその発言の先頭）から聞き直し、それ以前の本文を引き継ぎます。境界の古い認識を置き換えるので、単純な追記による二重登録はしません。抜けの補完中なら未処理の区間から、話者識別・整形中なら文字起こし済みの本文を使って後処理から再開します。モデルの内部状態までは保存しないため、境界付近の認識は中断せずに実行した場合と異なることがあります。

以前の版の途中保存では、同じ元音声を1件だけ選び、認識設定を当時の値に合わせてから再開してください。ファイル名と長さは確認しますが、元音声との完全一致は検証できません。古い補完データには実施済み区間の記録もないため、残る抜けを調べ直します。処理が実行中のデータや完成済みのデータは重ねて再開できません。

「途中保存・全編未完了」の間は本文の閲覧・ダウンロードができます。本文編集・AI校正・議事録生成は全編の処理が完了してから行ってください。

議事録や要約を作った後に本文・話者などを修正すると、結果欄の上と各文書に「更新前の内容です」と警告が出ます。文書を作り直すと解消します。以前の版で作った文書など、作成時の記録がない場合は「更新状況を確認できません」と表示します。元の文書は自動では書き換えません。

①は別プロセスで動きます。①が終わった時点でGPUのメモリが全部空くので、アプリを再起動しなくても③の gemma4 が速度を落とさずに動きます。

## できること

- **文字起こし**: faster-whisper large-v3 をGPUで動かします。既定では区間ごとに文脈をリセットし、雑音で生じた誤認識・繰り返し・発言の抜けが後まで続くのを抑えます。人名・用語辞書は最初の区間のヒントに使い、無音部分の誤認識（「ご視聴ありがとうございました」など）は取り除きます。速さは「精度優先」「バランス（約2.4倍速）」「高速（約8倍速）」から選べます。
- **音声の下処理**: 低音のうなりと高域ノイズのカット、背景ノイズ除去、「えー」「うーん」などのフィラー除去。どれも詳細オプションで切り替えられます。
- **句読点と文の区切り**: 話の間と文末の言い回しから「、」「。」「？」を補います。間が空いただけで文が途中で割れることはありません。「✂️ 文の区切り・句読点を整え直す」で、音声を解析し直さずに数秒でやり直せます。
- **話者識別と声紋**: pyannote で話者を分け、登録した声紋と照らし合わせて名前を付けます。人数は自動で推定します。結果がおかしい時は人数を指定して「👥 話者識別だけやり直す」を押せば、文字起こしはそのままで話者だけ数分で計算し直せます。
- **議事録**: 会議概要、要点サマリー、議題別の詳細、決定事項、アクションアイテム（表）、保留・検討事項、AIの意見の順にまとめます。長い会議は区間ごとに要約してから1本にまとめます。
- **字幕(SRT)編集**: 単語のタイミングから読みやすい長さで字幕を区切ります。1行の文字数・行数・秒数は調整できます。時刻の一括ずらし、重なりや速すぎの検出と自動修正、既存のSRT/VTTの読み込みもできます。
- **使うほど賢くなる**: 発言の修正を保存すると誤認識のパターンを覚え、同じ直しが2回以上たまったら次から自動で直します。声紋は会議のたびに育ちます（後述）。
- **その他**: 時刻をクリックするとその位置から再生、ボタン1つで文字起こし.md・議事録.md・字幕.srt をダウンロード、Word/PDF出力、過去の全会議の横断検索、複数ファイルの一括処理。

## 起動方法

| OS | 方法 |
|----|------|
| Windows | `run.bat` をダブルクリック |
| Mac / Linux | ターミナルで `./run.sh`（初回は `chmod +x run.sh`） |

初回はライブラリのダウンロードに数分から10分ほどかかります。NVIDIA GPUがあれば、CUDA版のPyTorchも自動で入ります。準備ができるとブラウザで `http://127.0.0.1:7860` が開きます。

## LLM（gemma4）の準備

校正・議事録・要約は、Ollama 上の gemma4 だけで動きます。

1. [Ollama](https://ollama.com) をインストールします。
2. モデルを取得します。既定は、gemma4 最上位（31B）の3bit量子化版です。16GBのVRAMに全部載るので、4bit版より約10倍速く動きます。
   ```
   ollama pull hf.co/unsloth/gemma-4-31B-it-GGUF:UD-IQ3_XXS
   ollama pull gemma4:12b-it-qat
   ```
   2つ目はメモリ不足で31Bが動かない時の代わりです。メモリが足りないと、まずGPUに載せる層を減らして再試行し、それでも駄目なら12Bに切り替えます。
3. 「⚙️ 設定」タブでモデルを選び、「LLM接続テスト」で確認します。思考モードをオンにすると議事録の質が上がりますが、時間は数倍かかります。

Ollama がなくても①の文字起こしと話者識別は動きます。

## 発言の抜け・聞き間違いを減らす設定

まず「精度優先」と、詳細オプションの認識方式「抜け・繰り返しを抑える（推奨）」を使ってください。
前の区間の誤認識や、何度も与えられる人名ヒントを引きずらないように認識します。声があるのに文字がない所は、これまでどおり自動で再認識します。

この方式は人名の漢字表記や句読点が揺れることもあります。その録音では「文脈・用語ヒントを優先（従来方式）」とも比較できます。用語辞書・人名の別名による表記の統一と、②のAI校正も引き続き使えます。高速モードは独自の一括処理なので、認識方式の選択は適用されません。

使った認識方式は結果の文字起こしと `meta.json` の `asr_decoding` に記録します。既定を変える場合は `settings.yaml` の `whisper.decoding` を `stable`（推奨）または `context`（従来方式）に設定します。

雑音で処理が進まないときは、詳細オプションの **「無音付近の誤認識を除外（内部スキップ）」** をOFF（チェックを外す）にしてから文字起こしを開始してください。ONは従来の動作、OFFは62分の録音を18分42秒で処理できた全編実験と同じ内部スキップ設定です。ノイズ除去とは別の機能で、OFFでも声の検出・アプリ側の誤認識除外・抜けの再認識は行います。ただし、内部で除外していた誤った文が残る場合があるため、本文を確認してください。

この切り替えは「精度優先」「バランス」に適用し、「高速」では操作不可・対象外になります。処理開始時の選択を使うため、実行途中の変更は次の処理から有効です。初期値はON。再起動後もOFFを初期値にする場合は、`settings.yaml` の `whisper.silence_guard` を `false` にします。実際の適用状態は文字起こしの先頭と `meta.json` の `asr_silence_guard`（ON=`true` / OFF=`false` / 高速=`null`）に残ります。

**使用する構成はWhisper → gemma4です。** Qwen3-ASR-1.7Bは比較試験で反復が残り、2026-10-08にユーザーの判断で使用を終了しました。通常アプリには組み込んでいません。保存済みの実験データと[導入手順・試験結果](docs/Qwen導入と比較.md)は記録として保持します。

## 環境音の区間を選んでノイズを減らす

「🔈 ノイズの見本で補正」タブで音声を入れ、説明者が話していない区間の開始・終了を指定します。秒数・`分:秒`・`時:分:秒`に対応します。「選んだ範囲だけを聞く」で見本を確認し、弱めの35から全体の除去を試してください。

除去後の音声に加え、削った音も `output/noise_profile_日時/` に保存します。**削った音に説明者の言葉が聞こえたら、除去を弱めるか見本を変えてください。** 人のざわめきは説明者の声と重なるため、この方法でも完全には分離できません。元音声は上書きしません。

同じ処理をコマンドでも実行できます（新しい出力フォルダを指定）。

```powershell
.\venv\Scripts\python.exe tools\try_noise_profile.py --audio "meeting.m4a" --start 0:00 --end 0:10 --strength 0.35 --output output\noise_trial_01
```

この見本方式は、現在の自動ノイズ除去とは別です。実装は[noisereduceの定常ノイズ処理](https://github.com/timsainb/noisereduce)を使っています。[Audacityの説明](https://manual.audacityteam.org/man/noise_reduction.html)にもあるように、時間で変わるざわめきや声と重なる音では、強く掛けるほど発言まで失う可能性があります。

## 話者識別・声紋登録

**高精度の pyannote を使う場合**: Hugging Face で [speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) と [segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0) の利用規約に同意し、発行したトークン（Read）を「⚙️ 設定」に入れてください。トークンがなくても、自前の声紋クラスタリングで動きます。

1. 「👤 人物・声紋登録」タブで名前を入れ、その人だけが話している10〜30秒の音声をアップロードするかマイクで録音して「🎤 声紋を登録」を押します。
2. 次からの文字起こしでは、登録した人に自動で名前が付きます。
3. 登録していない人は「話者A」のように表示されます。「話者に名前を付ける」で名前を入れて確定すると、その声紋も保存されます。

**声紋は会議のたびに育ちます。**「③ 📋 議事録を作る」を押すと、直した後の話者名をもとに、その会議の音声から1人だけが続けて話している所を3秒ずつ切り出して声紋に足します。話者交代の前後、声の重なり、小さな声、咳などは使いません。同じ会議で何度押しても置き換えになるので、同じ声が重複して溜まることはありません。

録音した日や部屋が違うと、同じ人でも声の類似度は下がります。そのため、しきい値に届かなくても他の人よりはっきり近ければ名前を付けます。別の人の名前が付いてしまう時は「⚙️ 設定」で「声紋一致のしきい値」を上げてください。

## 出力フォルダ

```
output/
└── 2026-10-01_1124_定例会議/
    ├── 文字起こし.md          ← 読みやすい文字起こし（話者・本文のみ）
    ├── transcript.md          ← 時刻・話者・赤字つき＋話者ごとの発話時間
    ├── transcript.srt / .vtt  ← 字幕
    ├── utterances.json        ← 発言データ（「過去の結果を開く」で再編集できる）
    ├── checkpoint.json        ← 音声認識の途中データ（完了後も保持）
    ├── resume_source.wav      ← 再開用の音量正規化済み音声（未完了時のみ）
    ├── resume_asr.wav         ← EQ・ノイズ除去済みの認識音声（必要な場合・未完了時のみ）
    ├── 文字起こし_途中.md     ← 途中保存の本文・未完了の注意書き
    ├── 文字起こし_途中_表示分.md ← 途中結果を履歴で開いた時点のダウンロード用本文
    ├── documents.json         ← 議事録・要約の作成時の入力と本文のハッシュ
    ├── speaker_clusters.json  ← 話者ごとの声の特徴（声紋学習用）
    ├── audio.m4a              ← 再生用の軽い音声
    ├── 議事録.md
    ├── 要約と考察.md
    └── meta.json              ← 処理の情報
```

途中保存は、新しい認識結果を受け取った時に約10秒間隔で行い、主認識の終了・抜けの補完・話者識別の前にも保存します。音声の準備が終わった段階でも空の途中データを保存するので、その後モデルの読み込みで失敗しても再開できます。音声変換・補正中に止まった場合は最初から実行してください。突然終了した場合は最後に保存できた分が残ります。

再開用の音声は録音1時間あたり約110MiB×1〜2本を使用します。未完了の間は保存フォルダごと保持してください。音声が欠けたり変更されたりしている場合は再開を止めます。完成版の保存に成功すると再開用WAVだけを削除し、本文・途中データ・再生用の `audio.m4a` は残します。

## ファイル構成

```
SimpleTranscriber/
├── app.py               # 画面（Gradio）
├── core/
│   ├── pipeline.py      #   ①の処理（文字起こし・話者分離・声紋学習）
│   ├── worker.py        #   ①を別プロセスで動かす（終わるとGPUメモリを全部返す）
│   ├── transcriber.py   #   faster-whisper（GPU自動検出）
│   ├── audio.py         #   ffmpeg変換・音質補正・ノイズ除去
│   ├── diarization.py   #   話者分離・声紋の登録と照合
│   ├── punctuate.py     #   句読点・文の区切り
│   ├── utterances.py    #   発言の組み立て・表示・Markdown・字幕
│   ├── llm.py           #   Ollama（gemma4）との通信
│   ├── minutes.py       #   校正・議事録・要約
│   ├── people.py        #   人物マスタ
│   ├── glossary.py      #   用語辞書・修正の学習
│   ├── export.py        #   Word / PDF 変換
│   └── search.py        #   横断検索
├── prompts/             # LLMへの指示文（書き換えて調整できる）
├── profiles/            # 人物マスタ・声紋・用語辞書（使うほど増える）
├── corrections/         # 学習した修正
├── output/              # 出力
├── settings.yaml        # 設定（自動で作られる）
├── run.bat              # Windows用の起動ファイル
└── run.sh               # Mac/Linux用の起動ファイル
```

`output/`・`profiles/`・`corrections/`・`settings.yaml` には会議の内容や声紋、トークンが入るため、Git には登録しません（`.gitignore` 済み）。

## 対応する入力形式

- 音声: mp3 / wav / m4a / ogg / flac / aac / wma / opus
- 動画: mp4 / mov / avi / mkv / wmv / flv / ts / m4v / webm

## 注意事項

- 終了する時は、ブラウザだけでなくコマンドプロンプト（ターミナル）も閉じてください。
- `large-v3` はCPUだと非常に遅いので、GPUのないPCでは `small` か `medium` をおすすめします（`auto` なら自動で選びます）。
- ffmpeg が必要です。Windowsは同梱のものを自動で探します。Macは `brew install ffmpeg` で入れてください。

## 動作環境

- Windows / macOS / Linux
- Python 3.10以上
- 推奨: NVIDIA GPU（VRAM 16GB）＋ CUDA
