# 設計判断ログ

- (2026-07-16) 文書出力はすべて .md（transcript.md/議事録.md/要約と考察.md）。SRTは字幕機能ファイルとして併存
- (2026-07-16) LLM接続: **Claude=公式anthropicSDK（ストリーミング受信）**、Ollama/OpenAI=httpx直叩き。（当初の「全部requests」から変更 — Claude APIはSDK利用が公式推奨のため）
- (2026-07-16) Claudeデフォルトモデルは `claude-opus-4-8`、Ollamaデフォルトは `gemma4`（ユーザー指定）、OpenAIは `gpt-4o`。すべて設定タブで変更可
- (2026-07-16) PDF生成は reportlab の日本語CIDフォント（HeiseiKakuGo-W5）。フォントファイル不要でWin/Mac両対応
- (2026-07-16) 話者分離は speechbrain ECAPA-TDNN + 自作逐次クラスタリング。**任意インストール**（torch+speechbrainが重いため）。未導入でも全機能が動く
- (2026-07-16) 修正学習は「同じ誤→正が2回出現で自動適用」（glossary.PROMOTE_COUNT）。誤学習防止のため
- (2026-07-16) whisperのモデルauto: GPU→large-v3 / CPU→small（CPUでlarge-v3は実用外のため）
- (2026-07-16) pip.exe直接実行がこの環境で壊れている（無出力でexit 1）。**必ず `python -m pip` を使うこと**
- (2026-07-16) **根本原因判明**: このフォルダは元 `E:\Developer\SimpleTranscriber` にあり `D:\TOOL\` へ移動された。venvの activate.bat / pip.exe には旧絶対パスが焼き込まれており、activate経由の起動は壊れている（グローバルPythonに化けて ModuleNotFoundError: gradio が発生）。対策として run.bat / run.sh は activate を使わず `venv\Scripts\python.exe` を直接呼ぶ方式に変更済み（フォルダ移動に強い）。venv自体の再作成は不要

# トラブルシュート記録

- (2026-07-16) run.batで ModuleNotFoundError: gradio → **原因: フォルダがE:\Developer\から移動されvenvのactivate/pip.exeが旧パス参照**。run.bat/run.shをvenvのpython直接呼び出し方式に修正して解決
- (2026-07-16) huggingface.coからの新規モデルDLが `SSL: CERTIFICATE_VERIFY_FAILED` で失敗（このPCはSSL検査環境の模様。large-v3は5/2キャッシュ済みだったため気づかなかった）。huggingface_hub 1.xのリトライバグで「client has been closed」と表示され原因が隠れる点に注意。**対策: truststore を導入し app.py 冒頭で inject_into_ssl()**（Windows証明書ストアを使用）→ 解決
