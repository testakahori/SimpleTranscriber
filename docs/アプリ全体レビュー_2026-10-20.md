# SimpleTranscriber 全体レビューと改善記録

対象: 音声の準備 → 文字起こし → 確認・修正 → 議事録・要約 → 書き出し・過去会議の検索。

評価: ローカルで完結し、処理を3段階に分けて人が確認できること、一時停止・再開・文書の更新警告があることは強み。一方で、編集を失わない仕組みと、結果を次の操作へ渡す導線が不足していた。今回はモデルを入れ替えず、確認済みの文章を守ることと、普段の操作を最後までつなぐことを優先した。

## 確認した手順と状態

1. **開始・音声準備: 改善済み。** 開始前から使えないボタンが多数有効で、履歴が選ばれているように見えて本文は空だった。履歴の初期値を空にし、結果に応じてボタンを有効化した。ノイズ補正後の音声をボタンで開始画面に渡し、二重処理を防ぐため背景ノイズ除去をOFFにする。
2. **確認・編集・復元: 改善済み。** 未保存の表示や編集履歴がなく、別操作で変更を失う可能性があった。未保存警告・操作制限・保存前の履歴・復元・古い画面からの上書き防止を追加した。
3. **AI校正・話者再識別: 不具合を修正。** 校正に返答がない行も完了扱いになり、再試行できなかった。話者再識別は単語データから本文を作り直して手修正を消していた。再確認の表示と再試行、修正済み本文の維持に変更した。
4. **議事録・書き出し・検索: 改善済み。** 書き出す会議を選び直す手間があり、表は単なる文字列になっていた。現在の会議を引き継ぎ、Word/PDFに実際の表を出す。検索から会議へ移動でき、本文の二重表示も避ける。

## 指摘と実装

| 優先度 | 問題 | 対応 | 根拠 |
| --- | --- | --- | --- |
| 高 | 保存後の誤編集や整形を戻せない | 会議内の `.history/` に編集前の本文・話者・会議情報を保存。復元操作も取り消せる | 手順2の画面、保存・整形・校正ハンドラ |
| 高 | 未保存の編集を別操作で失う | 未保存表示、履歴・AI操作の制限、明示的な破棄、ブラウザ終了時の警告 | 手順2の画面操作 |
| 高 | 別画面の古い本文から新しい保存を上書きできる | 保存元のハッシュを比較し、OSロック内で確認。競合時は保存前に停止 | 2つの状態から編集する再現テスト |
| 高 | 番号の誤編集や欠けた行が発言削除につながる | 番号・時刻を固定。欠落・重複・不正番号を拒否。学習は本文保存後 | 手順2、異常な編集表のテスト |
| 高 | 話者をやり直すと手修正が消える | 修正済み発言の本文と時刻を保持し、話者だけ付け直す | 元の単語と修正文が異なるテスト |
| 高 | AIが返さない行も「校正済み」 | 返答を採用できた行だけ完了。残りを再確認として再試行可能に | 欠落・不適切な短縮・重複回答のテスト |
| 中 | 「校正済みもやり直す」でAI修正文が対象にならない | AI修正は再実行し、人の手修正は保持 | 再校正のテスト |
| 高 | 複数のGPU処理が同時に動く | 認識・校正・文書生成・話者処理等を同じ実行枠にまとめる。一時停止の受付は別 | 画面イベント設定・既存テスト |
| 中 | 何の会議を表示しているか分かりにくい | 会議名、完了状態、音声長、発言数、校正再確認件数、次の操作を表示 | 手順1・2の画面 |
| 中 | 補正音声を保存し、手で再アップロードする必要がある | 補正音声から開始画面へ直接渡す | 30秒の合成音声を使った画面操作 |
| 中 | 議事録の表がWord/PDFで崩れる | 本物の表、セルの折り返し、複数ページでの見出しの繰り返し | DOCX構造・90行の表のPDF生成・PDF画像 |
| 中 | 検索が内部用本文を重複表示し、元の会議を開けない | 二重表示を除き、選んだ行の会議・文書を直接開く | 検索画面とテスト |
| 中 | 時刻クリックがマウス操作だけ | 時刻を名前付きのボタンにし、Enterキーでも再生 | ブラウザで20秒への移動と再生を確認 |
| 高 | 空の認識結果や空のAI回答から文書を作ってしまう | 発言がない場合は生成を止め、AIが空回答なら既存文書を保持 | 空入力・空回答のテスト |

## 検証と証拠

- 自動テストは **87件すべて成功**（既存69件＋追加18件）。保存・再開・一時停止に加え、復元、競合後の読み直し、保存失敗時の本文・派生ファイルの復旧、校正漏れ、手修正後の再確認表示の解除、修正文の維持、検索、表の書き出しを検証。
- 7870の専用画面で、編集 → 未保存警告 → 保存 → 編集前へ復元 → 文書の警告解除、検索 → 該当会議の議事録、Word/PDF生成、ノイズ補正音声の引き渡しを確認。
- PDFは画像化して表の枠・日本語・折り返しを目視確認。Wordは生成ファイル内の表構造とセル内容を確認。
- 元音声の代わりに合成音声と合成テキストを使用。実Whisper・gemma4の認識精度や生成品質を再測定した検証ではない。
- 実録音・声紋・人物辞書・ユーザー設定は変更していない。検証データは `output/20261020_アプリ全体レビュー/` に保存し、Git対象外とする。

画面は今回のレビューで取得したもの。開始前・編集前の画面を比較資料として保存し、改善後の復元、書き出し、補正音声の導線を記録した。`03-before-export.jpg` は一覧読み込み中のため正常画面の証拠には使っていない。書き出し一覧はタブを開く時に読み込む方式に変更し、改善後の表示を確認した。

## 残る制約と次の評価

- **認識精度は別途評価が必要。** 雑音・複数人の同時発話・人名に対する正確さは、この操作改善だけでは保証できない。次は実音声の短い複数区間について人が正解文を作り、抜け・誤変換・CERを比較する。Qwenは使わずWhisper → gemma4の方針を維持する。
- **復元の対象は会議の内容。** 人物辞書・修正学習・声紋は戻らない。画面にも明記した。履歴は自動削除しないため、編集を重ねると保存量が増える。
- **修正済みの文章の話者変更は発言単位。** 同じ修正済み発言に複数人がいる場合は最も長く話した人を採用し、手で確認してもらう。修正文を元の単語へ推測で分配しない。
- **一時停止は従来どおりASRの安全な区切りで反映。** AI校正・文書生成の即時停止や、再起動後も残る複数ファイルの待ち行列は今回追加していない。
- **アクセシビリティの全面検証ではない。** 時刻のキーボード操作は実確認済み。赤字のみに頼る確信度表示、編集表のスクリーンリーダー操作、拡大時の長文編集、Mac実機は追加検証が必要。
- **画面を閉じる確認はブラウザの制限を受ける。** 未保存の編集内容そのものを永続化する機能ではないため、保存完了を確認してから閉じる。
