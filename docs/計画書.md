# 1. ゴール（このツールが目指す姿）

> 音声・動画を投げるだけで、**高精度な文字起こし + 話者識別 + 議事録 + 要約・考察・ネクストアクション** が
> ぜんぶ自動で `output/` フォルダに整理されて出てくる。しかも**使えば使うほど賢くなる**。
> Windows でも Mac でも動く。

## 要望の整理（今回のオーダー全部入り）

| # | 要望 | 実現方針 | 難易度 |
|---|------|---------|--------|
| 1 | 文字起こし精度を極限まで上げる | large-v3モデル + GPU自動検出 + 用語辞書 + LLM二次校正 | ★★☆ |
| 2 | 議事録を自動生成（プロンプト改良） | 議事録プロンプト v2 + LLM連携 | ★★☆ |

# 2. 全体アーキテクチャ（進化後）

```
入力（音声 or 動画）
   │
   ▼
[1] ffmpeg 前処理 ──── 動画→音声抽出 / 16kHzモノラル正規化 / 音量ノーマライズ
   │
   ▼
[2] 文字起こしエンジン ─ faster-whisper large-v3（GPUあれば自動使用）
   │                      + VADフィルタ + word_timestamps + 用語辞書(initial_prompt)
   ▼
[3] 話者分離・声紋照合 ─ pyannote / ECAPA-TDNN埋め込み
   │                      → 声紋DBと照合 →「この声は坪内さん」
   ▼
[4] 後処理・校正 ─────── 人物マスタで名前置換（ボンギン→坪内）
   │                      低信頼度区間をLLMが文脈推測 → 赤字マーク
   ▼
[5] LLM生成 ──────────── 議事録 / 要約 / 考察 / ネクストアクション
   │
   ▼
[6] output/ 出力 ─────── 案件フォルダに全成果物を整理保存
   │
   ▼
[7] 学習フィードバック ─ ユーザー修正 → 辞書・声紋DBに反映（成長）
```

# 4. 人物マスタ（要望5: ボンギン=坪内 問題）

`profiles/people.yaml` に登録。UIに「人物登録」タブを新設して編集可能に。

```yaml
people:
  - display_name: 坪内        # 議事録での正式表記
    aliases:                   # 音声内で呼ばれる名前（すべて坪内に変換）
      - ボンギン
      - ぼんぎん
      - ボンギンさん
      - つぼうち
    voiceprint: 坪内.npy       # 声紋ファイル（あれば話者識別に使用）
    role: 代表取締役             # 任意: 議事録の文脈理解に利用
  - display_name: 田中
    aliases: [たなかさん, タナカ]
```

処理内容:
- 文字起こし結果内のエイリアスを正式表記に自動置換
- LLM議事録生成時にこのマスタをプロンプトに注入 →「ボンギンさんの発言は坪内と表記」
- Whisperの `initial_prompt` にも名前を入れて認識精度自体を向上

# 5. 声紋識別（要望4: この声は●●さん）

## 仕組み
1. **話者分離 (Speaker Diarization)**: 音声を「話者A/B/C」に自動分割
   - 第一候補: `pyannote.audio 3.x`（精度最強。初回のみHuggingFaceトークン必要、以降オフライン）
   - 完全オフライン代替: `SpeechBrain ECAPA-TDNN` + クラスタリング（トークン不要）
2. **声紋埋め込み**: 各話者の声を192次元ベクトル化
3. **声紋DB照合**: `profiles/voiceprints/` の登録済みベクトルとコサイン類似度で照合
   - 類似度 ≥ 0.75 → 「坪内」と自動ラベル
   - 未知の声 → 「話者A」と表示し、UIで名前を割り当てると**次回から自動認識**（成長ポイント）

## UI
- 文字起こし後、「話者A = ？」のドロップダウンで人物マスタから選択 or 新規登録
- 選択した瞬間にその会議の声紋が保存され、以後の会議で自動識別

## 出力例（transcript_speakers.md）
```markdown
**[00:01:23] 坪内:** それでは定例を始めます。
**[00:01:45] 田中:** 先週の<span style="color:red">進捗ですが</span>、資料の通りです。
```

# 6. 文字起こし精度の極限強化（要望1, 9）

## 6-1. モデル・エンジン強化
| 項目 | 現状 | 強化後 |
|------|------|--------|
| モデル | small (CPU固定) | **large-v3**（デフォルト）、UIでモデル選択可 |
| デバイス | CPU int8 | **CUDA自動検出** → GPUならfloat16で爆速&高精度、なければCPU |
| VAD | あり | あり + パラメータ調整（min_silence 500ms等） |
| 単語タイムスタンプ | なし | `word_timestamps=True`（赤字判定・SRT精密化に使用） |
| 用語ヒント | なし | `initial_prompt` に glossary.yaml + people.yaml の語を注入 |
| 言語 | 自動 | 日本語固定オプション（誤判定防止） |

## 6-2. 聞き取れない箇所の文脈補完 + 赤字表記（要望9）
1. faster-whisperの **単語ごとの確信度 (`word.probability`)** を取得
2. 確信度 < 閾値（例 0.5）の単語・区間を「低信頼」としてマーク
3. LLMに前後の文脈 + 用語辞書を渡して「ここは何と言った可能性が高いか」を推測させる
4. 出力での表現:
   - **Markdown/HTML**: `<span style="color:red">推測テキスト</span>`（Markdownビューアで赤表示）
   - **UI (Gradio)**: `gr.HTML` で赤色レンダリング
   - **プレーンtxt**: 色が使えないので `【推測: テキスト】` マーカー
5. 元の低信頼テキストも `meta.json` に保存（後から検証可能に）

## 6-3. LLM二次校正（オプション・強く推奨）
文字起こし全文をLLMに渡して:
- 同音異義語の修正（機会→機械、意義→異議 など文脈で判定）
- フィラー除去（「えーと」「あのー」）のON/OFF
- 句読点・段落の自然な整形

# 7. LLM連携方針（議事録・要約・校正の頭脳）

本ツールの売りは「完全ローカル」。これを壊さない2段構えにする。

| モード | エンジン | 特徴 |
|--------|---------|------|
| **ローカルモード**（デフォルト） | Ollama（qwen3, gemma3 等の日本語強モデル） | 完全オフライン維持。無料。機密会議OK |
| **クラウドモード**（任意） | Claude API (claude-sonnet-5) | 最高品質の議事録・考察。APIキーを設定した人だけ |

- 設定画面でモード切替。クラウドモード時は「外部送信されます」と明示警告
- LLM未設定でも文字起こし単体は今まで通り動く（グレースフルデグラデーション）

# 8. 議事録プロンプト v2（要望2: もらったプロンプトの改良）

現行プロンプトの良い点（事実のみ羅列 / チェックリスト化 / 見出しルール）は維持しつつ、以下を強化した v2 ドラフト。実装時に `prompts/議事録プロンプト_v2.md` として配置する。

```markdown
# 役割
あなたは一言一句を聞き漏らさないプロの書記です。文字起こし（話者名・タイムスタンプ付き）と
人物マスタを元に、正確で読みやすい議事録をMarkdownで作成してください。

# 入力
- 話者名付き文字起こし
- 人物マスタ（呼び名→正式表記の対応表。例: ボンギン→坪内）
- 補足情報（あれば）

# 絶対ルール
- 文字起こしに存在する発言のみを事実として記載。推測で事実を作らない。
- 文字起こし内で赤字（<span style="color:red">）の推測部分を議事録に使う場合は、
  議事録でも赤字を維持すること。
- 人名は必ず人物マスタの正式表記を使用（呼び名のまま書かない）。
- 決定事項と検討中事項を明確に区別する。

# 出力フォーマット
# 会議情報
- 日時 / 参加者（人物マスタの正式表記で） / 会議の目的（読み取れる範囲で）

# 全体的な要点
- 3〜5行で会議全体の結論を要約

# 決定事項
- 会議で「決まったこと」だけを列挙（決まっていないことは書かない）

# 会議の流れ
# 議題A（議題名）
- 誰が何を報告・提案し、どういう議論になったかを事実ベースで
# 議題B
- …

# アクションプラン
## （グループ名/会社名）
- [ ] タスク内容（期限が発言されていれば記載）
## （相手社）
- [ ] …

# 保留・宿題事項
- 結論が出ず持ち越しになった項目

# Markdownルール
- 水平線（---, hr）は使用しない
- 見出しは「#」のみ使用（##はアクションプランのグループ分けのみ許可）
- アクションプランはチェックリスト形式 `- [ ]`
- 担当者は原則書かない。グループ単位でリスト化する
```

### v1からの改善ポイント
1. **役割定義**を追加（LLMの出力品質が安定する）
2. **決定事項**セクション追加（会議で一番知りたい情報を分離）
3. **保留・宿題事項**追加（次回会議の冒頭確認に使える）
4. **人物マスタ連携**を明文化（ボンギン→坪内の自動適用）
5. **赤字推測の維持ルール**追加（情報の信頼度が議事録まで伝搬）
6. **参加者・日時**のヘッダ追加
7. PLAUD依存の記述を汎用化（本ツール内で完結する書き方に）

# 9. 要約・考察・ネクストアクション（要望10）

議事録とは**別ファイル** `要約と考察.md` を生成。会議以外の音声（講演・インタビュー・雑談メモ）にも使えるよう、議事録と分離するのがミソ。

```markdown
# 📝 要約（3行）
- この音声の内容を3行で

# 🔍 詳細サマリー
- 5〜10項目の箇条書き

# 💡 考察・解説（AIの読み解き）
- 「表面上はAの話だが、実質的にはBを懸念していると思われる」
- 発言の背景・意図・温度感の解釈
- ※ここは事実ではなくAIの解釈であることを明記

# ⚠️ リスク・注意点
- 聞き逃されている論点、矛盾している発言、決まっていないのに進んでいる事項

# 🎯 ネクストアクション（人物別）
## 坪内
- 資料Aを次回までに修正（根拠: 00:12:34の発言）
## 田中
- 先方に見積を送付（根拠: 00:25:10の発言）
## チーム全体
- …
```

- ネクストアクションには**タイムスタンプの根拠**を付ける（後から音声で確認できる）
- 議事録の「担当者は書かない」ルールとは逆に、こちらは**人物別**に整理（用途が違うため）

# 10. 成長する仕組み（要望6: 使うほど賢く）

| 学習対象 | 仕組み | 効果 |
|---------|--------|------|
| **声紋** | 会議ごとに話者を確定すると埋め込みを追記平均 | 認識精度が回を追うごとに向上 |
| **誤変換辞書** | UIでテキスト修正→保存すると diff を抽出し「誤→正」候補を `learned_words.yaml` に記録。次回から `initial_prompt` + 後処理置換に使用 | 社内用語・製品名の誤認識が消えていく |
| **人物マスタ** | 新しい呼び名を検出したらUIで登録提案 | 名前の間違いゼロへ |
| **用語辞書** | glossary.yaml を手動 + 自動で拡充 | 専門用語の認識率向上 |

修正diffの抽出は「編集前後の単語レベル比較（difflib）」で実装。同じ修正が2回以上発生したら辞書昇格、という閾値方式で誤学習を防ぐ。

# 11. Windows / Mac 両対応（要望7）

| OS | 起動方法 |
|----|---------|
| Windows | `run.bat`（既存を堅牢化。内容は英語のみで記述） |
| Mac / Linux | `run.sh` 新規作成（venv作成→pip install→起動を自動化） |

- ffmpeg依存: Windowsは `imageio-ffmpeg` パッケージで同梱、Macは `brew install ffmpeg` 案内 + 自動検出
- パス処理は全て `pathlib` に統一（`os.getcwd()` 直書きを廃止）
- GPU検出: Windows/Linux=CUDA、Mac=CPU（faster-whisperはMPS未対応のためint8最適化で対応）

# 12. 動画対応の堅牢化（要望8）

現状mp4はwhisper内部のffmpegで偶然動いているレベル。以下で堅牢化:
- 対応拡張子追加: `.mov` `.avi` `.mkv` `.wmv` `.flv` `.ts` `.m4v`
- 処理前にffmpegで **16kHz mono wav に明示変換**（これが精度にも効く）
- 音声トラックなし動画の事前検出とエラーメッセージ
- 長尺動画（2時間超）はチャンク分割処理でメモリ安定化

# 16. リスクと対策

| リスク | 対策 |
|--------|------|
| large-v3はCPUだと激遅（実時間の2〜4倍） | GPU自動検出 + モデル選択UIで逃げ道。「速度優先/精度優先」プリセット |
| pyannoteのHFトークン要求 | 初回セットアップガイド化 + SpeechBrain完全オフライン代替を併備 |
| LLM補完が「もっともらしい嘘」を書く | 必ず赤字表記 + 元テキストをmeta.jsonに保存 + 承認UI |
| Ollama未導入ユーザー | LLM機能なしでも従来機能は全部動く設計 |
| 声紋の誤認識 | 類似度閾値を保守的に設定。確信が持てない場合は「話者A(坪内?)」表記 |
| Macでの動作未検証 | Phase1でrun.sh追加後、実機検証項目をチェックリスト化 |

# 17. さらなる「つよつよ」アイデア（余裕があれば）

- **リアルタイム文字起こし**: マイク入力をライブで文字起こし（会議中に使える）
- **Obsidian連携**: 議事録を直接Vaultに出力（既にObsidian環境あり）
- **NotebookLM連携**: 議事録を自動でノートブックに登録して横断質問可能に
- **音声前処理強化**: ノイズ除去（RNNoise/DeepFilterNet）で汚い録音の精度UP
- **感情・温度感分析**: 「この議題のとき場が紛糾していた」等のメタ情報
- **複数ファイル一括処理**: フォルダごとドラッグ→全ファイル自動処理キュー
- **Word/PDF出力**: 議事録をそのまま提出できる形式に
- **検索機能**: 過去の全議事録を横断全文検索「あの件いつ話したっけ？」

# 18. まず何から始めるか（推奨）

**Phase 1 から着手推奨。** 理由:
1. output整理・Mac対応・動画堅牢化・人名置換は既存コードの延長で確実に実装できる
2. large-v3化だけで体感精度が劇的に上がる（small→large-v3は別物レベル）
3. Phase 2以降のLLM・声紋は、Phase 1の土台（フォルダ構造・人物マスタ）の上に載る設計のため

「Phase 1 やって」と言ってもらえれば即着手できます。
