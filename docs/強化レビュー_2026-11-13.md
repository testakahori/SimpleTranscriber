# SimpleTranscriber 強化レビュー（2026-11-13）

ユーザーの指摘: ①議事録・考察が文字起こしと違う意味になる ②女性2人の区別がつかない ③漢字の誤変換 ④修正がやりづらい ⑤起動が遅い。これに加えて全体を見直し、気づいた改善も実装した。Whisper → gemma4（Ollama）の方針、別プロセスでのGPU処理、途中保存・再開・編集保護は維持している。

## ① 議事録・考察の意味が変わる — 原因と対策

**原因（実測で確認）**

- LLMの入力長の見積もりが実際と合っていなかった。`llm.fits_context` は「文字数×1.1＋出力分8192 ≤ 上限16384」で判定していたため、プロンプト（約3000字）を引くと **文字起こしは約4400字（約10分の会議）までしか直接入らず**、それを超える会議はすべて「区間メモ」に圧縮してから議事録化していた。
- その区間メモの区切りは18000字固定で、上限16384トークンを明らかに超えていた。Ollama は上限を超えた入力の **先頭を黙って切り捨てる**（システムプロンプト側が欠ける）ので、メモの段階で指示や冒頭の発言が失われ、意味の取り違え・捏造の温床になっていた。
- gemma4 の日本語の実トークン比を Ollama の `prompt_eval_count` で実測したところ、議事録プロンプト＋技術文書で **1.63〜1.72字/トークン**（0.58〜0.61トークン/字）だった。以前の見積もり（1.1トークン/字）はおよそ2倍過大。
- 31B 3bit版は `num_ctx=32768` でも 16GB VRAM で全層GPU（`ollama ps` で 100% GPU）、生成 24.3 tok/s・プロンプト処理 767 tok/s で、16384 の時（23.3 tok/s）と速度が変わらないことを確認した。

**対策**

| 変更 | 内容 |
|---|---|
| `core/llm.py` | `TOKENS_PER_CHAR = 0.8`（実測0.6の安全側）、出力予約 6144 トークン。`input_budget_chars` で system を除いた入力可能文字数を計算し、`_num_ctx` は上限を超えない。超える時は警告ログ |
| `core/config.py` | 既定の `ollama_max_ctx` を 32768 に（settings.yaml も同じ値に更新済み）。約2時間（約30000字）の会議まで文字起こし全文から議事録を作る |
| `core/minutes.py` | 区間メモの区切りを上限から逆算（固定18000字を廃止）。直前の区間の末尾3行を参考として添え、重要な発言は要約せず「」で引用する指示に変更。区間メモの各項目に時刻を残す |
| `prompts/議事録プロンプト_v4.md` | 否定・条件・推量・質問/断定・賛否・誰の発言かを落とさない、複数人の意見を1つにまとめない、数字・日付は表記をそのまま使う、**各項目に「（根拠 hh:mm:ss）」を付ける** |
| `prompts/要約と考察プロンプト.md` | 詳細サマリー・リスク・ネクストアクション・考察に根拠時刻 |
| `core/minutes.py verify_document` | **項目ごとの照合**: 文書を箇条書き・表の行・要約段落に分け、各項目が示す時刻の前後±75秒（時刻が無い項目は語の重なり）の発言だけを根拠候補として渡し、「OK／修正／確認できず」を判定させる。修正は書式・表の列数・長さの比を検査してから適用。根拠が無い項目は「（文字起こしで確認できず）」を付記。会議の長さに関係なく1項目あたりの根拠は小さく収まり、区間メモ経由の議事録でも元の発言と突き合わせられる |
| 温度 | 校正・議事録・区間メモ・照合は 0.1（事実の書き写し）。考察は従来の 0.3 |
| 画面 | 議事録・要約タブに「作成後に…文字起こしと照合して直す」チェック（既定ON。設定 `llm.verify_documents`）。結果メッセージに「N項目を照合、M項目を修正、K項目は根拠が見つからず」を表示。照合に失敗しても下書きは保存する |

**限界**: 照合はLLMの判定なので万能ではない。考察・AIの意見は解釈なので照合しない。議事録の根拠時刻が実際の発言とずれていると、±75秒の窓から外れて「確認できず」になることがある（その場合は本文で確認する）。実会議でのCER・正確さの数値評価は未実施。

## ② 女性2人の区別がつかない

話者分離（pyannote・自前クラスタリングの両方）は声の似た2人を1つの話者にまとめることがあり、1クラスタには1人しか名前を付けられないため、もう1人の発言はその人の名前で出ていた。モデルの入れ替え（2026-10-04の比較でECAPAが最良）ではなく、登録済み声紋の使い方を変えた。

- **自動の見直し `diarization._refine_with_voiceprints`**: 登録済みの声紋が2人以上ある時、2.5秒以上の発言のまとまりごとにECAPA声紋を取り、登録済みの別の人物に「しきい値＋0.05以上」かつ「今の人物より0.10以上近い」区間が **合計6秒・2区間以上** あれば付け替える。単発の誤判定は採用しない。未登録の話者（話者A）の区間は、2番目の候補より0.10以上はっきり近い時だけ。pyannote・自前の両方の経路で実行し、結果欄・再識別のメッセージに付け替え数を表示。
- **手動の分割 `diarization.split_speaker`**: 「修正」タブの「話者を分ける」。選んだ話者の発言ごとに声紋を取り k-means で2〜3人に分け、大きい組は元の名前、残りは「<名前>（2）」。登録済みの人物にしきい値以上で近い組には名前を付ける。組同士の類似度（0.85以上なら分けにくい）と候補を表示。別プロセスで実行し、編集履歴に保存前の状態を残す。
- **声紋の候補列**: 「話者に名前を付ける」の表に、各話者が登録済みの誰にどれだけ近いかを近い順に表示（numpyのみ・即時）。2人が同じ候補に近い時に分割の判断材料になる。
- 「話者A（2）」のような分割後の仮名は、声紋学習・Whisperのヒントの対象外（`UNNAMED_RE`・`_PLACEHOLDER_RE`）。

**限界**: 登録済みの声紋が無い2人は自動では分けられない（手動分割は可能）。声紋の精度はデータ量で決まるので、本人だけの音声を複数回登録し、会議で名前を確定して学習させることが前提。合成ベクトルでの単体テストは通したが、実録音での効果測定は未実施。

## ③ 漢字の誤変換

- **一括置換**（「修正」タブ③）: 「誤」「正」を入れて件数と出現例を確認し、全発言を置き換えて保存。置き換えた発言は引き続きAI校正の対象（手修正扱いにしない）。既定で `glossary.learn_pair` に1回分を学習し、同じ置換が2回たまると次回の文字起こしから自動適用（同音異義語を1回で全文に広げない。用語辞書タブの学習済み修正で確認・削除可）。
- **AI校正の改善**: 会議メモ（議題・参加者）と「過去に人が直した誤変換の例」（最大40件）を校正プロンプトに渡す。直後の発言も参考に添える。温度0.1。対象を「すべて／要確認の発言だけ（速い）」から選べる（既定は従来どおりすべて）。
- 校正プロンプトに、会議の話題に合う漢字を選ぶ指示と例を追加。

## ④ 修正がやりづらい

従来は4列の表で、音声は別タブ、要確認の行を目で探す必要があった。「修正」タブを作業順に組み替えた。

1. **話者に名前を付ける**（候補列・話者を分ける）
2. **発言ごとに聞きながら修正する**: 本文の各発言に「✎ 修正」ボタンを追加（押すと修正タブに切り替わり、その発言が開く）。欄には「▶ この発言を再生」（その発言の範囲だけ再生して自動で止まる）、前後2発言の薄い表示、話者ドロップダウン（既存の話者から選択・新規入力可）、本文、「保存して次へ」「保存」「この発言を削除」。「◀ 前へ」「次へ ▶」「次の要確認へ ⏩」（末尾で先頭に戻る）、番号入力で「開く」。
3. 一括置換 4. AI校正（対象選択） 5. 表でまとめて修正（従来の表は折りたたみに）6. 編集履歴から復元 7. 話者識別・文の区切りをやり直す

保存は1件ごとに即時（`job_history` の競合検査・修正学習は従来どおり）。保存・削除の対象は番号欄ではなく「画面に開いている発言」の記録（会議フォルダ・位置・開いた時の本文と話者）で、別の会議や、開いた後に別の操作で変わった発言には書き込まない。書きかけのまま移動しようとすると止める。編集前の履歴は1件ごとではなく10分に1回残す（1件ごとに残すと履歴が数百MBに肥大し、画面の切り替えも遅くなる）。表に未保存の編集がある間は1件保存を受け付けず、先に表を保存するか破棄するよう案内する。

Gradio 6.6 の制約で分かったこと（実画面で確認）: 非表示タブの部品は一度開くまで描画されないため、本文→修正の受け渡し用の隠し欄はタブの外（画面外）に置く。textarea に JavaScript で値を書いて input イベントを送っても Gradio は拾わない。JavaScript だけのイベント（`fn=None, js=...`）に `.then` は続かない。そのため「隠しボタンの js が値を Gradio の欄に書く → その欄の `.change` で Python を呼ぶ」方式にした。

## ⑤ 起動が遅い

実測（warm）: `python app.py` からポート開放まで 8.4秒。cold では gradio の読み込み 11.6秒・torch 35秒超。`run.bat` は毎回 `pip install -r requirements.txt` と torch の読み込み確認を行っていた（ネットワーク次第で数十秒）。

- `run.bat`: 前回導入時の `requirements.txt` のコピー（`venvequirements.installed`）と `fc /b` で比較し、同じなら pip・torch 確認を飛ばす。`run.bat --check` で強制。
- `app.py`: GPUの有無の確認を別プロセス（`core.pipeline:probe_devices`）で行い `output/.device_probe.json` に記憶。アプリ本体では torch・ctranslate2 を読み込まない。Ollama のモデル一覧（停止時は3秒待ち）は画面表示後に裏で取得。`diarization.unload()` は torch を未読込なら触らない（初回のAI校正ボタンで数秒止まっていた）。
- 結果: ポート開放まで 1回目 6.4秒（GPU確認が裏で走る）、2回目 3.6秒（gradio の読み込み2.4秒が大半）。run.bat 側の削減分（pip確認・torch確認）は環境により数秒〜数十秒。

## レビュー指摘への対応（別エージェントによるコードレビュー）

実装後に別のレビュー担当が差分を読み、重大5件・中9件・軽10件を指摘した。重大・中はすべて対応し、軽微なものも大半を直した。

| 指摘 | 対応 |
|---|---|
| 修正欄の保存・削除が番号欄の発言に対して行われ、表示中と違う発言を上書きし得る | 「開いている発言」の記録（会議・位置・本文・話者）を `gr.State` に持ち、保存・削除はそれに対して行う。別会議・開いた後に変わった発言は拒否 |
| 会議の切り替え・再開・分割後に修正欄が古いまま | 会議を開く・再開完了・分割後は修正欄を開き直す（途中保存は空にする） |
| 分割で元の名前が大きい組に付き、本人の声が「岡田（2）」として学習される | 登録人物の組に元の名前。「名前（n）」はどの名前でも仮名扱いで学習・ヒントの対象外。既存の「（2）」と重ねない。空の組は除く |
| 照合の「修正」が番号の取り違えで別項目の内容を上書きする／根拠時刻が消える | 修正前後の類似度（根拠時刻を除く本文で0.5以上）、同じ回の他の項目との近さ、根拠時刻の維持、表の列数、長さ比で検査 |
| 部分的な根拠で段落を書き換えて縮める | 要点サマリー・要約の段落と、語の重なりでしか根拠を探せない項目は「OK／確認できず」だけ（修正しない）。根拠は複数の時刻すべてに近い行を優先 |
| 1件保存のたびに数MBの履歴が増え、画面が遅くなる | 履歴は10分に1回。履歴一覧の表示名はファイルの更新時刻でキャッシュ |
| 書きかけの修正欄が移動で消える | 本文・話者が開いた時と違えば移動を止める |
| 一括置換が手修正扱いになりAI校正から外れる／1回で全文に自動適用 | 手修正扱いにしない。学習は2回で自動適用 |
| 区間メモの参考行で予算を超える／メモ自体が上限を超える | 参考行は合計400字まで・予算から差し引く。メモが収まらなければメモをさらにメモにする（2段まで） |
| 会議メモの行が根拠に使われる | 時刻で始まる発言行だけを根拠にする |
| CUDA版torchの導入失敗後に再確認しない | 失敗時はスタンプを書かず次回も確認 |
| 校正の既定が「要確認のみ」になり従来より狭い | 既定は「すべて」。要確認のみは速い選択肢 |
| 議事録 32768→照合 16384 でモデルを読み直す | 一度使ったコンテキスト長をプロセス内で維持 |
| 照合の途中でLLMが落ちると全部捨てる／リスク項目に「確認できず」 | そこまでの修正を残し理由を表示。リスク節は付記しない。行末の改行用スペースも維持 |
| 見直しの失敗で話者分離の結果が消える／未登録話者の区間が似た登録人物に奪われる | 見直しは失敗しても無視。今のクラスタの代表より0.10以上近い時だけ付け替え |
| run.bat が LF のままだと goto が不安定 | `.gitattributes` で `*.bat` を CRLF 固定 |

## 使い方のポイント（ユーザー向け）

1. 声紋は「本人だけの音声を複数回」登録し、会議で名前を確定して学習させる。同じ名字の人はフルネームで。
2. 文字起こし後、結果欄の「声紋で N 区間の話者を付け替え」を確認。2人が混ざっていたら「話者を分ける」。
3. 本文の「✎ 修正」か「次の要確認へ」で聞きながら直す。同じ誤変換は一括置換。
4. 議事録は照合ONのまま作る。「（文字起こしで確認できず）」が付いた項目は本文の該当時刻を聞き直す。
5. 起動は run.bat のまま。ライブラリを入れ直す時だけ `run.bat --check`。
