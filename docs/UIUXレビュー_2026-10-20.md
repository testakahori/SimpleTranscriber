# SimpleTranscriber UI/UXレビューと実装記録

対象: ローカルの会議音声を文字起こしし、人が聞き直して修正し、議事録・要約を保存する一連の操作。2026-10-20の全体レビュー（PR #21）を土台に、実画面で操作と情報の配置を見直した。

評価: 途中保存・再開、編集保護、文書の更新警告があることは強み。改善前は、開始ボタンや履歴が画面下に埋もれ、確認・修正の操作と文書の作成ボタンが離れていた。今回は「次にどこを操作するか」と「何を確認すべきか」が分かる画面に整えた。

## 1. 音声の準備・開始 — 改善済み

- 「新しく文字起こし」と「保存した会議」を左側のタブに分けた。新規ではアップロード、速さ、開始ボタンが最初に見える。
- 会議日時・メモ・話者数・モデル等は「会議情報・認識の設定」にまとめた。既定値と認識設定の意味は維持した。
- PCの動作環境は「設定」タブへ移し、常用画面の上部を短くした。
- ファイル未選択時の開始ボタンは無効。一時停止は、その画面で開始した処理がある時だけ有効になり、受付後は「保存して停止中…」になる。
- 補正音声を渡すと、「新しく文字起こし」を開いて開始できる状態にする。二重の背景ノイズ除去は引き続きOFFにする。

根拠: 改善前の [開始画面](../output/20261020_UIUXレビュー/01-before-start.jpg)、改善後の [開始画面](../output/20261020_UIUXレビュー/04-after-start.jpg)、[補正音声の受け渡し](../output/20261020_UIUXレビュー/10-noise-transfer.jpg)。

## 2. 本文の確認・修正 — 改善済み

- 結果を「本文」「修正」「議事録」「要約と考察」に整理し、本文から「修正へ進む」で移動できる。
- 修正表を右側の広い領域に配置。内容欄を広げ、「修正を保存」「保存済みの内容に戻す」を表の上に置いた。
- 話者名の確定、AI校正、履歴からの復元、話者識別・整形のやり直しは、目的が分かる名前の折りたたみ欄にまとめた。
- 不明瞭な箇所・AIの推測・校正未完了に「要確認」を表示。「次の要確認へ」で順に移動できる。色だけでなくバッジと下線を使い、移動先にキーボードのフォーカスを合わせる。
- 表示上の「発言 N」は修正表のNoと対応する。1発言が複数の文に分かれて表示されても、元の編集行を探せる。
- 薄い補足文字と主ボタンの色を濃くし、フォーカス枠を追加した。

根拠: 改善前の [編集画面](../output/20261020_UIUXレビュー/02-before-edit.jpg)、改善後の [本文](../output/20261020_UIUXレビュー/05-after-review.jpg)、[要確認へのフォーカス](../output/20261020_UIUXレビュー/05b-review-focus.jpg)、[修正画面](../output/20261020_UIUXレビュー/06-after-edit.jpg)。

## 3. 議事録・要約の作成と保存 — 改善済み

- 各文書のタブに、案内・作成ボタン・Markdownダウンロード・本文をまとめた。
- 未選択、途中保存、未保存の編集、発言なし、未作成、更新前、更新記録不明、最新の状態に応じて案内を変える。
- 作成済みの文書は「作り直す」と表示する。文書生成後は案内も明示的に再更新する。ディスク上の文書だけが変わった時も「未作成」の表示が残らない。
- 全体には更新前の文書名を短く表示し、詳細は該当タブにまとめた。本文内に同じ警告を繰り返さない。ダウンロードにも更新前の表示を残す。
- 会議を開き直すと、前の会議の「保存しました」「作成しました」などのメッセージを消す。

根拠: 改善前の [文書画面](../output/20261020_UIUXレビュー/03-before-document.jpg)、改善後の [作成済み文書](../output/20261020_UIUXレビュー/07-after-document.jpg)、[更新前の案内](../output/20261020_UIUXレビュー/08-stale-document.jpg)。

## 4. 履歴・再開・検索 — 改善済み、一部追加検証の余地あり

- 履歴と「途中保存から再開」を同じ場所に配置。途中保存では処理位置と再開方法を表示し、編集・文書作成は完了まで無効にする。
- 検索0件は空の結果表と検索語を変える案内を表示する。「該当なし」をクリック可能な会議のように扱わない。
- 検索結果の件数と行を選ぶ操作を明示し、結果から会議を開く既存機能を維持した。

根拠: [途中保存の画面](../output/20261020_UIUXレビュー/09-partial-meeting.jpg)。検索は空入力・0件・一致あり・結果選択を実画面で確認した。

## 優先順位と判断

| 優先度 | 発見した問題 | 実装上の判断 |
| --- | --- | --- |
| 高 | 開始・履歴・再開を見つけるために長くスクロールする | 作業の入口を左上にまとめる |
| 高 | 文書を見ている場所と作成ボタンが離れている | 各文書タブに操作と状態をまとめる |
| 高 | 要確認箇所を長い本文から目で探す | 件数、ジャンプ、編集行番号の対応を追加 |
| 中 | 修正表が狭く、補助操作が常時並ぶ | 本文の領域を広げ、補助操作を折りたたむ |
| 中 | 使えない操作の理由・文書の状態が分かりにくい | 状態に応じた案内、作成後の明示的な表示更新 |
| 中 | 前の会議の成功メッセージが残る | 切り替え成功時に消す |
| 中 | 注意点が色だけに依存し、補足文字が薄い | バッジ・下線・フォーカスと配色を改善 |
| 低 | 検索0件でも結果らしい1行が出る | 結果と案内を分離する |

## 検証結果と限界

- 自動テスト: `venv\Scripts\python.exe -m unittest discover -s tests -v`、**91件成功**（既存87件＋UI状態・要確認表示・停止状態・検索0件の4件）。文書警告の既存テストも新表示に合わせた。
- 実画面: Windows、Gradio 6.6、独立ポート7870、1280×720で検証。合成テキスト・30秒の合成音声・固定のAI回答を使用。新規開始、履歴、編集と保存、要確認への移動、文書作成、検索、補正音声の受け渡しを確認した。
- キーボード: 「次の要確認へ」のEnter操作で発言2へ移動し、次の操作で発言4へ移動。件数表示とフォーカスも確認した。
- ダウンロード: UIから取得した要約と保存元のSHA-256が一致した。取得ファイルは [ダウンロード確認_要約と考察.md](../output/20261020_UIUXレビュー/ダウンロード確認_要約と考察.md)。
- 一時停止の実行中・受付後・完了後の切り替えと画面ごとの所有は自動テストで確認。今回は長時間の実Whisper処理を回していない。
- 狭い画面で縦に並べるCSSを追加したが、モバイル実機、200%拡大、ダークモード全画面、スクリーンリーダーは未検証。アクセシビリティ全面対応を保証するレビューではない。
- 音声認識・LLMの精度向上を検証したものではない。Whisper → gemma4、内部スキップの選択、途中保存・復元の保護を維持した。

画面証拠・合成データ・取得ファイルは `output/20261020_UIUXレビュー/` に保存した。`output/` はGit対象外のため、上の証拠リンクはこのPCの作業フォルダで参照する。実録音・人物辞書・声紋・ユーザー設定は変更していない。起動済みのアプリには再起動後に反映される。
